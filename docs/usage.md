# 使い方ガイド

## アプリ内ガイドページ（/guide）

ヘッダーの **ガイド** リンク（ダッシュボード・プロジェクト画面の両方にあります）から、アプリ内ガイドページ `/guide` を開けます。次の内容をいつでも参照できます。

- **はじめかたチェックリスト**: プロジェクト作成 → WBS分解 → 依存設定 → ベースライン保存 → 進捗入力・監視 の推奨手順
- **PMBOK の5つの Focus Areas（立ち上げ / 計画 / 実行 / 監視・コントロール / 終結）とアプリ操作の対応表**
- **PMBOK用語集**: WBS・クリティカルパス・トータルフロート・依存タイプ（FS/SS/FF/SF）・ベースライン・PV/EV/SPI などのひとこと定義と使いどころ。検索フィルタとページ内アンカーで素早く引けます

## 推奨フロー

1. ダッシュボードでプロジェクトを作成
2. **WBS** タブでタスクを階層登録（所要日数・進捗）
3. **ネットワーク図** で**依存関係を設定**し、クリティカルパスを確認
4. **ガント** でスケジュールを俯瞰し、計画が固まったら**ベースラインを保存**
5. 実行中は WBS で**進捗を入力**
6. ダッシュボードで **SPI を確認**し、遅延の兆候を早期に把握
7. **リスク / 関係者** タブで登録簿を随時更新

## Docker 起動

```bash
cp .env.example .env   # TG_AUTH_TOKEN を設定
pnpm start             # compose 起動 + 準備完了後にブラウザが開く
# 停止: Ctrl+C
```

手動起動:

```bash
export TG_AUTH_TOKEN=tg_anon_xxxxxxxx
docker compose up --build
```

`pnpm start` 利用時も、準備完了後に http://localhost:3000（または 3000 が使用中の場合は空きポート）がブラウザで開きます。データは `/data` ボリュームに永続化されます。

## WBS（タスクの階層と編集）

**WBS** タブでタスクを階層的に登録します。行をクリックすると**タスク詳細**ページが開き、名称・作業内容・担当・所要日数・進捗を編集できます。

- 子を持たないタスク＝**ワークパッケージ**（WP バッジ付き）。所要日数と進捗はワークパッケージに入力します
- 親タスクの所要日数・進捗は子の値から**自動集計（ロールアップ）**されるため、直接入力する必要はありません
- タスク名が空・空白のみ、所要日数が 0 未満や数値以外の場合は保存前にエラーが表示されます。進捗は 0〜100 の範囲に丸められます
- **子タスクの追加**: タスク詳細の「+ 子タスクを追加」で下書きフォームが開きます。**保存**を押すまでタスクは作成されません。キャンセルすると何も追加されません
- **タスクの削除**: タスク詳細ページの「削除」ボタンから行えます。子タスクがある場合はまとめて削除されます

## 依存関係エディタ（ネットワーク図）

**ネットワーク図** タブでタスク間の依存関係を直接編集できます。

- 先行タスク・後続タスクを選んで依存を追加
- 依存タイプを選択: **FS**（終了→開始）/ **SS**（開始→開始）/ **FF**（終了→終了） / **SF**（開始→終了）
  - 選択中のタイプの説明がフォームの下に表示されます。**FS**（前のタスクが終わったら次を開始）が最も一般的で、迷ったら FS を選んでください
- **ラグ**（待ち日数。負値はリード）を日数で指定
- エッジにはタイプとラグがラベル表示され、凡例で読み方を確認できます
- 同じ先行・後続の組み合わせを二重に登録しようとすると、送信前に「既に登録されています」と表示されます。タイプやラグを変えたい場合は一覧から削除して追加し直してください
- 依存がループ（循環）になる場合は、関与するタスク名と「逆向きの依存を削除するか、この依存を見直してください」というヒントが表示されます

依存を変更するとクリティカルパスと開始/終了日が自動で再計算されます。

## スケジュールベースライン（ガント）

ベースラインは「承認した時点の計画のスナップショット」です。保存しておくと、その後の計画変更や遅れを当初計画との差として測れます。計画が承認されたタイミングで **ガント** タブからベースラインを保存します。

- **灰色のバー** = ベースライン保存時（承認時）の計画
- 色付きのバーが現在の計画。バー内の濃い塗りつぶしは**進捗率**
- **赤い縦の点線** = 今日の位置
- 各タスクに終了日の差異が **±n日** で表示されます（**+n日 = 計画より遅延（赤）**、−n日 = 前倒し（緑）、±0 = 計画どおり）

ガント画面では「ベースラインと差異バッジの見方」を開くとこの凡例をいつでも確認できます。チャートの直上にもバー・進捗・今日線の凡例が表示されます。

ベースラインは複数保存でき、不要になったものは削除できます。

### ベースライン API

```
POST   /api/projects/:id/baselines   # 現在の計画をベースラインとして保存
GET    /api/projects/:id/baselines   # ベースライン一覧
DELETE /api/baselines/:id            # ベースライン削除
```

## 簡易EVM と SPI（ダッシュボード）

ベースラインを保存すると、日数ベースの簡易 EVM 指標を算出します。

- **PV**（計画価値）: 基準日までに完了している計画の日数
- **EV**（出来高）: 進捗率を加味した実際の達成日数
- **SPI** = EV ÷ PV（スケジュール効率）

ダッシュボードの各プロジェクトカードに SPI バッジが表示されます。

| SPI | 表示 | 意味 |
|-----|------|------|
| 1.0 以上 | 緑 | 順調（計画どおり以上） |
| 0.85 以上 1.0 未満 | 黄 | 注意（やや遅延） |
| 0.85 未満 | 赤 | 遅延（対策が必要） |

## 登録簿（リスク / 関係者）

- **リスク登録簿**: 確率・影響・状態を select で編集。確率×影響の**リスクスコア（1〜9）**がバッジで表示され、高スコアほど優先対応
- **ステークホルダー登録簿**: 権力・関心の高低から**権力・関心グリッド**の区分（注意深く管理 / 満足状態を維持 / 常に情報提供 / 監視）を自動表示

## JSONエクスポート / インポート

プロジェクト一式（タスク・依存・マイルストーン・リスク・関係者など）を JSON でバックアップ・移行できます。

1. **エクスポート**: 画面のエクスポート操作、または `GET /api/projects/:id/export` で JSON をダウンロード
2. **インポート**: 画面のインポート操作で JSON を選択（または `POST /api/projects/import` に送信）すると、新しいプロジェクトとして取り込まれます

```bash
# CLI での例
curl -s http://localhost:3000/api/projects/<id>/export > project.json
curl -s -X POST http://localhost:3000/api/projects/import \
  -H "Content-Type: application/json" -d @project.json
```

## コメント投稿時のローカル LLM 変更提案

タスク詳細の **進捗コメント** を追加すると、ローカル LLM（デフォルト: Ollama）が計画を分析し、タスク・依存・マイルストーン等の変更提案をコメント入力欄の下にカード表示します。提案ごとに **反映** ボタンで計画に適用できます（自動反映はしません）。

### 前提（Ollama）

1. [Ollama](https://ollama.com/) をインストール
2. モデル取得: `ollama pull qwen2.5:7b-instruct`（推奨。8GB RAM 未満は `qwen2.5:3b` も可）
3. 起動: `ollama serve`（常駐。macOS アプリから起動する場合は不要）
4. 無効化する場合のみ `.env` に `TPC_LOCAL_AGENT=off`

Docker 起動時はホスト上で Ollama を動かし、コンテナから `host.docker.internal:11434` 経由で接続します（`docker-compose.yml` で設定済み）。

### 操作

1. タスク詳細ページでコメントを入力し **コメントを追加**
2. 保存成功後、AI が分析（数十秒かかる場合あり）
3. 提案カードの **反映** で変更を適用、**スキップ** で個別に dismiss

Ollama 未起動時もコメント保存は成功します（AI 提案のみ省略）。

### モデル・プロバイダの変更

| 環境変数 | 説明 |
|----------|------|
| `TPC_OLLAMA_MODEL` | Ollama モデル名（例: `qwen2.5:7b-instruct`） |
| `TPC_OLLAMA_BASE_URL` | Ollama API の URL |
| `TPC_LOCAL_AGENT=openai_compatible` | LM Studio 等の OpenAI 互換 API を利用 |
| `TPC_OPENAI_COMPATIBLE_URL` | 互換 API のベース URL（例: `http://127.0.0.1:1234/v1`） |
| `TPC_OPENAI_COMPATIBLE_MODEL` | 互換 API のモデル名 |

## AIアシスト（プロンプト方式）

MCP 非対応の ChatGPT 等向け:

1. プロジェクト画面の **AIアシスト** タブを開く
2. 目的（WBSドラフト / タスク分解 / リスク / 依存）を選択
3. **プロンプトをコピー** して AI に貼り付け
4. 返ってきた JSON を貼り付けて **取り込む**

取り込み時の支援機能:

- ` ```json ` などのコードフェンスは**自動で除去**されるため、AI の回答をそのまま貼り付け可能
- 取り込み前に**プレビュー**で内容を確認してから反映
- JSON は Zod で検証され、不正な場合は**項目別のエラーメッセージ**が表示されます
